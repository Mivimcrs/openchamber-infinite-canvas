# 维护者指南

## 仓库结构

仓库根就是可安装的扩展包：

```
package.json           manifest + 版本号（宿主据此判断更新）
icon.svg
status/index.html      卡片 / 面板页面
status/main.js         构建产物（IIFE，必须提交）
service/main.mjs       构建产物（ESM，必须提交）
源码/                   TypeScript 源码、构建与自检脚本
文档/
.github/workflows/     ci.yml（push/PR 自检）+ release.yml（tag 发版）
```

宿主安装时不会编译，**改完源码必须 `npm run check` 并提交构建产物**。CI 还会用 `git diff --exit-code -- status service` 验证提交的产物与源码一致。

## 本地构建

```powershell
cd 源码
npm install
npm run check
```

`check` 依次执行：

1. `tsc --noEmit`；
2. `scripts/build.mjs`（产物落到仓库根）；
3. `scripts/check-manifest.mjs`（与宿主同一份 zod schema）；
4. `scripts/check-guest.mjs`（官方 `openchamber-guest-check`）；
5. `scripts/check-repo.mjs`（本机路径 / 私有目录 / 疑似密钥 / 版本一致性）。

## 发版

1. 改根 `package.json` 与 `源码/package.json` 的 `version`（两处必须一致，`check-repo` 会校验）。
2. 提交并推送 `main`。
3. 打 tag 并推送：

   ```powershell
   git tag v0.2.0
   git push origin v0.2.0
   ```

4. `release` 工作流：安装依赖 → 构建自检 → 打 `openchamber-infinite-canvas-<版本>.zip` → 创建 Release。

## 从 URL 安装与更新

```
https://github.com/Mivimcrs/openchamber-infinite-canvas
```

- 宿主读仓库根 `package.json` 的 `version`，与已装版本做 semver 比较；有新版本时在扩展页提示更新。
- 回滚装旧 tag：`https://github.com/Mivimcrs/openchamber-infinite-canvas#v0.1.0`。
- 更新会整份替换安装副本，**安装目录里的手改会丢**；所有改动必须进本仓库。

## 发布前检查清单

- [ ] `npm run check` 全绿
- [ ] `git diff --stat` 里构建产物与源码一起变了
- [ ] README 的前置条件、安装命令与实际行为一致
- [ ] 没有把本机路径、token、画布 API Key 写进任何文件
